시점 이동 때 부품 바닥은 원래 설치 위치에 고정하고, 높이에 따라 윗면을 옮겨 그 사이에 옆면을 연결합니다. 나사·단자·명판·덮개와 전선 끝도 같은 표면을 따라 움직이며, 클릭은 표시 위치에서 원래 작업 좌표로 변환합니다. [수정 전후 확대 비교·검증](docs/anchored-projection.md)

## 2.28.0 · 사진 기준 IO링크 외형·덕트와 찬넬 뒷면 접착

사용자가 제공한 IO링크 사진을 기준으로 40·50핀 커넥터, 회백색 몸체, 두 줄의 은색 나사 단자와 조임판, 투명 힌지 커버와 견출지, 노란 DIN 찬넬 고정 레버를 다시 그렸습니다. [사진 반영 항목·실제 화면](docs/io-link-graphics.md)

재료함에서 꺼낸 덕트·찬넬은 뒷면이 위로 보입니다. 바닥에 놓고 뒷면에 양면테이프를 붙인 뒤 철판에 설치하면, 테이프는 아래로 가고 열린 정면이 보입니다. 들고 있는 재료를 재료함에 돌려놓는 버튼도 활성 상태로 유지합니다. [작업 과정·확인](docs/frame-back-tape.md)

## 2.27.1 · 떠 있는 테두리와 덕트 파손 표시 수정

기구들의 중복 외곽선과 옆면의 긴 경계선을 제거하고, 둥근 몸체에 바로 붙는 면으로 수정했습니다. 조작판 뒤 표시등·스위치·HMI는 실제 몸체 크기에 맞춥니다. 파손한 덕트 이음부에는 이빨과 옆면이 다시 통로를 막아 보이지 않도록 했습니다. [수정 전후 화면·검증](docs/graphics-fixes.md)

## 2.27.0 · 기구 전체의 입체감과 재질

## 2.26.0 · 콘센트·플러그 전원과 덕트 이빨 아래 배선

동작 검사 재료에서 접지 콘센트를 바닥에 놓고, 손 도구로 플러그를 선택한 뒤 콘센트 가운데를 누르면 연결됩니다. 플러그를 다시 누르면 빠지고 실제 회로 전원이 차단됩니다. 검정 코드는 풀린 곡선으로, 색선 분기는 더 좁고 자연스럽게 수정했습니다. 선 정리는 이빨 아래 위치로도 진입하며 전선이 이빨 뒤에 가려집니다. [조작·검증](docs/mains-and-duct-entry.md)

## 2.16.1 · Windows 설치형 게임

**Electron + electron-builder**로 Windows 10/11 64비트용 설치형 앱을 추가했습니다. [설치 파일 다운로드](https://github.com/leemangi0923/HTML/releases) · [설치·저장·빌드 설명](docs/desktop.md)

설치 후 바탕화면 바로가기로 실행하고 F11로 전체 화면을 전환합니다. 게임과 그림을 포함해 인터넷 없이 실행하며, 배선 목록 TXT·CSV는 파일 저장 창으로 내보냅니다. 앱을 재시작하거나 새 버전을 설치해도 같은 앱 저장 공간을 사용합니다. **브라우저 작업과 앱 작업은 별도로 저장**합니다. 기존 `index.html` 웹 버전도 계속 사용할 수 있습니다.

`npm start`로 개발 실행, `npm run dist:win`으로 Windows 설치 파일을 만듭니다. GitHub의 **Windows installer** 빌드가 Windows 검사 후 설치 파일을 생성하고, 버전 태그는 Releases 다운로드로 배포합니다. 개발용 Node.js는 22.12 이상이 필요합니다.

## 2.15.0 · 완성 배선 성능 개선

작업판을 기구·전선·커버·조작판 등으로 나누어 **바뀐 SVG 부분만 갱신**합니다. 버튼·센서·릴레이 상태 변화나 확대 상세 표시에서는 기존 전선 경로와 압착단자 그림을 재사용합니다. 조작판 앞면의 좌우 반전 단자·전선 경로도 다시 사용하며, 실제 배선·기구 변경 시에는 기존 무효화 경로로 다시 계산합니다.

타이를 끄는 입력은 마지막 위치를 보관하고 **프레임당 한 번 계산·표시**합니다. 타이가 당기는 선의 모양만 다시 계산하며, 놓기·취소·포인터 캡처 해제·창 포커스 이탈 때 대기 중인 위치를 동기화해 저장합니다. 전기 연결·밴드 고정 구간·되돌리기·기존 저장 형식을 유지합니다.

같은 완성 배선 장면의 합성 입력 120개에서 타이 이동 계산은 120→1회, 교체되는 SVG 노드는 5,186→76개였습니다. 이 수치는 입력 처리·DOM 교체 측정이며 화면 FPS가 아닙니다. 같은 환경의 전후 시간 측정과 재현 방법은 [성능 점검](docs/performance.md#2150-완성-배선의-부분-갱신과-타이-이동)에 있습니다.

## 2.14.0 · 실전 고장 실습

메인 메뉴의 **실전 고장 실습**에서 **입문(고장 1개)** 또는 **도전(고장 2개)**을 선택합니다. 기존 고장 10종을 활용하며, 도전은 실제 회로 검사에서 각 고장의 증상이 따로 드러나는 조합 19개로 제한합니다. 난이도별 출제 목록을 섞어 한 바퀴 동안 같은 사례를 다시 뽑지 않고, 새 바퀴 첫 사례도 직전 사례와 다르게 합니다.

처음에는 생성한 회로를 실제 계산한 **증상만** 보여줍니다. 작업판의 MCB·조작판·팩으로 확인하고 테스터(M)로 측정한 뒤 배선·퓨즈·타이머를 직접 고칩니다. 힌트는 선택해서 **범위 → 측정할 곳 → 원인** 순서로 열고, 두 번째 단계부터 측정 위치를 확대·표시할 수 있습니다. 틀려도 실습은 계속됩니다. **동작 검사 받기**는 현재 결선의 배선 검사 15개와 운전 검사 11개로 판정하며 예시 전선 쌍을 요구하지 않습니다. 다른 단자 위치를 쓰는 동등한 배선도 통과합니다.

실습의 배선·힌트·검사 횟수·경과 시간은 `t1sim.fault`에 별도로 저장합니다. 메인에서 실습 메뉴로 돌아가 **실습 이어 하기**로 계속합니다. 새로고침 후 재입장하면 MCB·버튼·팩 같은 실시간 조작 상태는 초기화되고 저장된 작업 상태를 복원합니다. 자유 작업·시험 작업·연습 통과 기록과 공유하지 않습니다. **같은 고장 다시**는 같은 사례를 초기화하고, **다른 고장 풀기**는 새 사례를 뽑습니다. 실습에서는 예시 채우기·배선 불러오기·시연을 제공하지 않습니다.

사용자 선택에 따라 전체 작업 백업과 동작 기록창은 진행하지 않으며, 추가 성능 개선은 2.15.0에서 적용했습니다. 기존 연습 챕터 7은 그대로 유지합니다.

## 2.13.0 · 2D 시뮬레이터로 정리

3D 작업실 메뉴·브라우저 실행 모듈·Three.js 의존성과 관련 검증을 제거했습니다. 예전 `lab-3d.html` 주소(회로 체험 쿼리 포함)는 기존 2D 메인으로 이동합니다. 메인에는 연습·자유·시험·선 따기 연습·도움말 다섯 항목을 유지하고 마지막 도움말 카드를 넓혔습니다. 기존 자유·시험 작업과 연습 기록은 그대로 사용합니다.

Godot 프로젝트·다운로드 파일·사용자가 제공한 원본 모델은 개발을 중단한 기록으로 보존합니다. 관련 도구가 쓰던 `lab-3d/reference`와 교복 마크 자료도 보존하지만 웹 3D 화면은 더 이상 실행하지 않습니다.

다음 업데이트 후보와 우선순위는 [2D 업데이트 계획](docs/2d-update-plan.md)에 정리했습니다. 2.14.0에서 실전 고장 실습을 구현했으며 나머지 상태는 계획 문서에 표시합니다.

## 2.9.1 퀴즈 제거

메인 메뉴에서 퀴즈를 제거하고 문제은행·이미지·출제 화면·진행 저장 코드를 정리했습니다. 퀴즈를 대체했던 3D 미리보기도 2.13.0에서 제거했습니다. 배선 오류 안내와 기존 연습·자유·시험·선 따기 연습·도움말은 유지합니다.

## 2.9.0 배선 오류 안내

일반 배선·전원 RTE·컨베이어 결선에서 거부된 연결의 양쪽 단자를 붉게 표시하고, 선택한 단자 이름·이유·다음 조치를 안내창에 표시합니다. ‘위치 보기’로 해당 지점을 확인하고, 성공적으로 연결하거나 닫기/Esc/모드 전환으로 안내를 해제합니다. 실제 회로 검사와 기존 연결 허용 기준·감점 여부를 유지합니다.

## 2.8.0 전원 케이블 갈·파·초 세 가닥 연결

전원 케이블은 **갈색 R·파란색 T·초록색 E** 순서입니다. 재료함에서 들어 제어판 아래 빈 바닥에 내려놓고, 각 선 끝과 단자대 아래쪽 단자를 차례로 눌러 한 가닥씩 연결합니다. 세 가닥이 모두 올바르게 연결돼야 정상 전원으로 인정합니다.

R/T는 실제 배선의 차단기 각 극에 맞아야 하며, E는 전원·직류 신호와 분리된 접지 전용 단자에 연결합니다. R/T 뒤바뀜, E의 전원·신호 오결선, 중복 단자, 닫힌 커버, MCB가 켜진 상태의 전원선 조작을 막습니다. 단자대 위치는 고정하지 않으며 내부 배선까지 맞게 옮긴 위치도 허용합니다. 연결 후 내부 배선을 바꾸거나 잘못된 저장 데이터를 읽어도 전원 회로를 재검사합니다. E 검사는 이 모델의 접지 전용 망 분리 확인 범위이며 접지 저항 등 실제 설비의 검사를 대신하지 않습니다.

연결한 선 끝을 다시 선택하면 그 한 가닥을 빼서 옮길 수 있습니다. 전원 케이블 몸체를 손으로 들면 세 가닥이 분리되며 다시 바닥에 놓을 수 있습니다. 부분 연결 상태·바닥 위치는 저장/되돌리기를 지원합니다. 기존 두 가닥 케이블 저장은 R/T 위치를 유지하고 접지 전용 단자를 찾아 E를 복원합니다. 연습·시연·할 일 안내도 세 가닥 방식으로 바뀌었습니다.

## 2.7.2 휠 버튼 화면 이동 최적화

휠 버튼 드래그·왼쪽 드래그·터치 확대의 카메라 반영을 프레임당 한 번으로 합칩니다. 드래그 시작 때 화면 크기를 읽어 재사용하고, SVG 갱신 직후 크기를 다시 읽는 작업을 줄였습니다. 이동 중에는 포인터 강조를 숨기고, 놓기·취소·포인터 캡처 해제·창 포커스 이탈 시 대기 중인 최종 위치를 동기화합니다. 확대 배율에 따른 기구 상세 표시도 유지합니다.

측정 방법과 한계는 [성능 점검](docs/performance.md)에 있으며 `CHROMIUM_PATH=/usr/bin/chromium npm run benchmark:pan`으로 입력 묶음 처리를 재현할 수 있습니다.

## 2.7.1 헬리컬 밴드 안의 전선 고정

밴드를 감은 뒤 케이블 타이를 묶거나 옮겨도 밴드 안의 전선과 덕트 쪽 경로는 고정됩니다. 밴드가 끝나는 곳부터 조작판 단자까지 드러난 전선만 부드럽게 움직입니다. 일부만 감았을 때는 실제로 감싼 구간만 고정하고 양쪽 노출 부분을 각각 움직입니다. 기존 배선·타이·저장 형식은 유지합니다.

## 2.5.3 표시등 진입 경로 정리

왼쪽으로 진입하는 표시등 배선에 남아 있던 위쪽 고리를 없애고, 연결 방향으로 바로 이어지는 곡선으로 바꿨습니다. 기존 저장 작업의 타이는 새 전선 경로에 맞춰 한 번 옮기며 연결 대상·개수·조임 상태를 유지합니다.

## 2.5.2 마우스 조작 성능

바뀌지 않은 전선의 경로·거리 계산 자료를 재사용하고, 포인터 강조를 화면 프레임에 맞춰 한 번만 그립니다. SVG 내용이 같으면 DOM을 교체하지 않습니다. 전선 수정·되돌리기·타이 이동 시에는 계산 자료를 다시 만듭니다.

JavaScript와 CSS를 별도 파일로 옮기는 것 자체는 프레임 개선이 아니므로 단일 HTML 실행 방식은 유지합니다. 측정 방법과 결과는 [성능 점검](docs/performance.md)에 있습니다.

## 2.5.1 표시등 배선 모양

HMI 아래쪽 표시등의 전선은 단자 왼쪽에서 들어오도록 90도로 꺾입니다. 같은 나사에 연결한 두 선은 위아래로 나란히 놓이며, 케이블 타이로 묶어도 단자 옆 직선 구간을 유지합니다. 전기적 연결과 저장 형식은 바뀌지 않습니다.

## 2.5 단자대와 배선 자유도

- 상단 **단자대 견출지** 또는 **견출지(L)** 도구로 단자대의 흰 이름표를 눌러 편집합니다. 빈칸·중복 이름도 가능하며 이름표는 전기적 기능을 지정하지 않습니다.
- S+ 등 외부 선을 다른 번호로 옮겨도, 내부 배선과 외부 결선이 함께 맞으면 실제 회로로 작동·검사합니다. 단자대 번호만으로 AC/DC를 정하지 않습니다.
- 전원 케이블은 꽂을 R선 단자와 T선 단자를 차례로 선택합니다. 전원 위치도 이름표와 별개이며 1·2번으로 고정되지 않습니다.
- 배선 목록에서 예시와 다른 선을 오답으로 표시하지 않습니다. 배선 검사는 외부 전원선과 컨베이어 선을 연결한 뒤 진행합니다.
- 추가로 발견한 고정 조건과 남은 한계는 [배선 자유도 점검](docs/wiring-flexibility.md)에 정리했습니다. 연습용 예시·배치·조작판 조건이 모두 자유화된 것은 아닙니다.

## 2.4 초보자를 위한 기구 해설

**기구 해설(I)** 도구로 설치된 기구를 누릅니다. 기본 화면은 다음 순서로 보여줍니다.

1. 기구의 실제 모양과 하는 일 한 줄
2. 현재 내 배선에서 계산한 상태
3. 릴레이는 두 갈래 길 그림, 타이머는 3단계 순서와 남은 시간
4. 직접 조작해 볼 방법이나 꼭 기억할 내용

단자 번호·모델명·전문 결선도는 **단자 번호·자세한 정보가 필요할 때**를 펼쳐서 확인합니다. 다른 기구로 바꾸면 다시 접힙니다. 창을 열어 둔 채 손(H) 도구로 버튼과 센서를 조작하면 그림과 설명도 실시간으로 바뀝니다. 해설을 보는 것만으로 기구나 배선이 바뀌지는 않습니다.

시험 중에는 해설을 숨기며 제출 뒤 다시 사용할 수 있습니다. 작업판에 선이나 접점 상태를 덧그리는 기능은 없습니다. 기존 저장 데이터 형식도 유지합니다.

## 2.2 기능

- 채점표의 미완료·감점 항목에서 **관련 위치 보기**를 누르면 부품이나 단자로 이동하고 빨간색으로 강조합니다. 자유 모드와 시험 제출 후에 사용할 수 있습니다. 동작 항목은 검사할 관련 부품·단자를 보여주며, 구체적인 원인은 감점 설명과 테스터로 확인합니다.
- **단자 검색**에서 `R3`, `PLC P20`, `TB 1번`, `부저`처럼 기호나 한글 이름으로 설치된 단자를 찾습니다. 조작판 단자는 필요하면 뒷면으로 전환합니다.
- **연결 추적**은 현재 꽂은 전선, 단자대 위아래·SMPS 공통선, 컨베이어 결선을 따라 연결된 단자와 전선을 강조합니다. 접점의 통전 상태와 전압은 테스터로 확인합니다.
- 강조는 Esc, **강조 지우기**, 작업 변경·초기화·모드 전환 시 해제됩니다. 저장 데이터 형식은 기존 버전과 같습니다.

## 자동 검증

Node.js 22.12 이상이 필요합니다.

```sh
npm ci
npx playwright install chromium
npm test
```

Linux에서 브라우저 시스템 라이브러리도 필요하면 `npx playwright install --with-deps chromium`을 사용합니다. 기존 Chromium을 사용할 때는 `CHROMIUM_PATH=/usr/bin/chromium npm test`로 실행합니다. npm 캐시 경로가 쓰기 금지된 환경에서는 `npm ci --cache /tmp/html-npm-cache`를 사용할 수 있습니다.

검증은 임시 로컬 HTTP 서버와 별도의 브라우저 저장 공간을 사용하며 사용자 작업은 건드리지 않습니다. 외부 폰트 없이도 실행합니다.

검증 대상:

- 정답 배선의 회로 검사 15개, 컨베이어 동작 검사 11개, 만점 30점
- 고장 10종 각각의 검출·감점 및 복구 후 통과
- 채점 위치 이동과 작업 상태 보존
- 기호·한글 검색, 실제 배선 추적, 검색 입력 중 도구 단축키 방지
- 빈 작업, 모드 전환, 시험 중 채점 위치 안내 제한
- 자유·시험 작업의 독립 저장 및 새로고침 복원
- 모바일 화면의 검색창과 위치 이동
- 릴레이의 실제 4극 전환과 초보자용 길 그림, 타이머 순시·한시·남은 시간과 전원 OFF 복귀
- 표시 접점과 회로 계산의 일치, 미장착 소켓, 기구 해설의 읽기 전용 조작
- 모든 설치 기구의 쉬운 역할·현재 상태, 기본 화면에서 전문 용어와 단자 정보 숨김
- 선택형 상세 정보, 작업판 접점 표시 제거, 시험 제한, 좁은 화면·어두운 테마의 해설 창

GitHub Actions는 push와 pull request에서 같은 검증을 실행합니다. 브라우저 조립 작업 전체를 수동으로 완주하는 테스트는 포함하지 않습니다.

2.14.0 검증: 고장 10개·도전 19개 모두의 검출·부분 복구·완전 복구, 조합별 독립 증상, 중복 없는 출제, 힌트 단계와 위치 표시, 새로고침 이어 하기와 다른 모드 저장 보존, 실제 마우스로 테스터 측정·단자 배선 후 통과, 단자 위치를 바꾼 동등한 회로 허용, 되돌리기 중 힌트·검사 횟수 유지, 모바일·어두운 테마와 같은 사례 재시작.

2.15.0 검증: 버튼 동작 중 고정 기구·전선 노드 및 경로 재사용, 기존 전선 겹침 순서, 타이 입력 묶기와 마지막 좌표 저장·되돌리기, 놓기·취소·캡처 해제·포커스 이탈 후 늦은 프레임 방지. 변경 전·후의 앞면·뒷면·PLC ON·컨베이어 운전 화면을 같은 조건으로 캡처해 작업판 픽셀이 일치함을 확인했습니다.

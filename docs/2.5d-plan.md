# 2.5D 작업판 구현 계획

사용자가 원하는 것은 **현재 작업판을 조금 비스듬히 보면서, 화면을 옮기면 부품의 옆면·겹침·깊이 차이가 조금씩 달라지는 모습**입니다. 현재의 정면 배선 작업을 기반으로, 부품에는 높이를 주고 카메라는 좁은 범위에서 움직이는 2.5D 작업 화면을 목표로 합니다.

이 문서는 전체 구현 계획입니다. **v2.23.0에서 1차 시연을 구현했습니다.** [1차 실행·검증 기록](2.5d-stage1.md). 2~8차는 아직 구현하지 않았으며 현재 게임의 기본 작업 화면은 2D입니다.

## 화면과 조작

- 처음에는 정면에서 약 10~15도 기울인 모습으로 제안합니다. 부품의 윗면과 옆면이 조금 함께 보여야 합니다. 각도 범위는 첫 시연에서 조정합니다.
- 휠 버튼을 누르고 화면을 옮기는 현재 조작을 유지합니다. 이동 방향에 따라 시야 각도가 소폭 달라져, 머리를 조금 옆으로 옮겨 작업판을 보는 느낌을 줍니다. 바닥에 가까운 찬넬과 높은 릴레이는 서로 다른 정도로 움직여 보입니다.
- 일반 마우스 이동만으로는 카메라를 흔들지 않습니다. 배선·측정·타이 이동·전선 정리 등 정밀 작업을 잡은 동안 각도를 고정합니다. 놓았을 때 갑자기 정면으로 튀어 돌아오는 움직임도 피합니다.
- 휠 확대/축소, 제어판·조작판·컨베이어 위치 보기, 태블릿의 두 손가락 이동/확대를 지원합니다.
- `정면 보기`, `각도 고정`, `2D / 2.5D`를 제공합니다. 정밀 배선 시에는 바로 정면으로 바꿀 수 있어야 합니다.
- 도구 줄·재료함·회로도·설명창·타이머 설정창은 화면에 반듯하게 남습니다. 단자 이름표도 화면을 향해 읽기 쉽게 표시하고, 강조 표시의 연결점은 실제 단자에 붙입니다.

## 표현 방식

현재 HTML/Electron과 시뮬레이터를 계속 사용하면서, **작업판을 그리는 부분에 경량 WebGL 렌더러를 추가**하는 방향을 권장합니다. 구현에는 Three.js 같은 라이브러리를 검토하되, 부품의 단순한 두께·옆면과 제한된 카메라에 집중합니다. 캐릭터·보행·실습실 공간을 만드는 작업은 이번 계획 범위에 포함하지 않습니다.

기존 SVG는 정면 재질과 제품 표기, 도면·설명용 그림으로 활용합니다. 실제 물체는 단순한 입체 형상에 정면 그림을 붙이는 혼합 방식으로 구성합니다. SVG 전체를 CSS로 한 번 기울이는 것만으로는 부품마다 다른 옆면과 깊이 차이를 만들 수 없으므로 최종 방식으로 삼지 않습니다.

| 대상 | 표현 |
|---|---|
| 철판 | 얇은 두께·절단면·타공 |
| 찬넬 | 낮은 금속 단면·접힌 턱·원래 타공 |
| 덕트 | 바닥·높은 빗살 벽·독립된 커버 |
| 스토퍼 | 찬넬에 걸린 몸체·옆면·고정 나사 |
| 소켓·릴레이·타이머 | 소켓보다 높은 본체, 단자와 몸체의 높이 차이 |
| PLC·SMPS·서보 | 단순 외장과 커넥터·단자 높이, 현재 제품 표기 |
| 전선 | 기존 평면 경로에 단자·노출 구간·덕트 바닥의 높이 부여 |

처음 높이는 표현용 상대 높이로 검증하며 실제 제품 치수라고 단정하지 않습니다. 실측 또는 제조사 치수와 비교해 조정할 수 있도록 표시용 메타데이터로 분리합니다.

## 현재 코드에서 필요한 준비

회로·채점·저장은 `S`, `TERMS`, 전선의 mm 좌표와 단자 ID를 중심으로 동작합니다. 이 부분을 유지하고 표시용 높이는 따로 둡니다. 카메라 이동이 `commit()`, 배선 변경, 동작 검사 무효화 또는 랭킹 시간/점수 변경으로 처리돼서는 안 됩니다.

현재 `toWorld()`는 SVG 직사각형의 가로·세로 비율로 마우스를 mm 좌표로 변환합니다. `zoomAt()`, 화면 이동·핀치, 견출지 선택창 위치, 돋보기와 일부 강조 표시도 이 평면 계산을 사용합니다. 원근이 생기면 이 계산을 그대로 쓸 수 없습니다.

공통 화면 좌표 계층을 먼저 만듭니다.

- `project(worldPoint)`: mm 좌표와 표시 높이를 화면 위치로 변환.
- `pick(screenPoint, tool)`: 카메라에서 쏜 선이 실제로 보이는 단자·기구·바닥 중 어디에 닿는지 찾음. 클릭한 물체의 높이를 포함해 기존 작업 명령에 넘길 좌표/ID를 결정.
- `projectTerm(id)`: 표시 높이를 포함한 단자 위치. 작은 단자 선택은 화면 픽셀 거리와 가려짐을 함께 확인.
- `fit/zoom/pan`: 같은 카메라·투영 정보를 사용. 확대 시 포인터 아래의 작업 지점을 최대한 유지.

이 계층은 기존 2D 모드에서는 지금과 같은 결과를 내야 합니다. 2.5D 모드에서는 높이가 있는 물체를 철판 높이로 잘못 역변환하거나, 커버 뒤의 단자를 뚫고 고르는 문제가 없어야 합니다.

`world123Parts()`와 `setSceneParts()`의 기구별 분리, `wirePts()`의 경로 재사용 구조를 활용할 수 있습니다. 렌더러는 기존 작업 명령을 호출하되 회로 로직을 별도로 복제하지 않습니다.

## 차수별 진행 계획: 총 8차

기존의 네 단계는 큰 방향이고, 실제 구현은 **검증 가능한 결과물 여덟 개**로 나눕니다. 기구 외형, 단자 조작, 기본 배선, 전선 정리를 분리해 각 변경의 영향을 확인합니다. 차수는 작업 범위의 단위이며 하루 또는 대화 한 번이라는 기간을 뜻하지 않습니다.

| 차수 | 목표 | 직접 확인할 결과물 |
|---|---|---|
| 1차 · 구현 | 입체감·카메라 시연 | 철판·덕트·찬넬·스토퍼의 옆면이 화면 이동에 따라 달라지는 별도 시연 |
| 2차 | 기존 게임에 시점 기반 연결 | 같은 작업 상태를 2D와 개발용 2.5D에서 보고 화면 좌표·확대·이동을 정확히 처리 |
| 3차 | 제어판 기구 외형·조립 | 소켓부터 PLC·SMPS·서보까지 입체화하고 장착·타공·고정·커버 조작 연결 |
| 4차 | 기구 조작·단자 선택 | 각도별 단자 선택, 스위치·버튼·퓨즈·릴레이·타이머 조작과 이름표 |
| 5차 | 기본 배선 | 높이가 다른 단자 사이에 전선을 꽂고 빼며 덕트 안으로 자연스럽게 연결 |
| 6차 | 전선 정리·측정 | 케이블 타이·헬리컬 밴드·전선 이동과 테스터를 2.5D에서 사용 |
| 7차 | 조작판·컨베이어·모드 연결 | 조작판 앞뒤·바닥 전원선·컨베이어와 연습·시험·고장·시연 안내까지 연결 |
| 8차 | 성능·호환성 검증과 정식 배포 | 완성 작업에서도 부드러운 화면, 저장 호환, 2D 복귀, Windows 설치형 |

각 차수에 확인용 화면이나 실행 가능한 시연과 변경·검증 기록을 남깁니다. 1~7차는 개발용 미리보기로 다듬고, 전체 조작을 검증한 8차에서 정식 2.5D 선택 기능으로 배포합니다. 기존 2D 작업 화면은 그동안 계속 사용할 수 있게 유지합니다. 정식 기능과 미리보기는 UI에서 구분합니다.

### 1차 · 입체감과 카메라를 먼저 확인

철판 한 장에 덕트·찬넬·스토퍼만 배치한 별도 시연을 만듭니다. 부품 두께, 옆면, 단순한 음영과 높이에 따른 시차를 표현합니다. 제한된 각도와 휠 버튼 화면 이동, 확대/축소, 정면 보기와 각도 고정을 구현합니다. 오프라인 실행과 WebGL 사용 가능 여부도 여기서 확인합니다.

**완료 기준:** 정면·좌측·우측에서 같은 스토퍼의 옆면이 달라지고, 화면 이동이 갑자기 튀지 않아야 합니다. 표시한 시험 지점을 눌렀을 때 선택 위치가 맞아야 합니다. 이 결과물로 사용자가 원하는 각도와 입체감의 기준을 잡습니다. 전체 게임 카메라는 아직 교체하지 않습니다.

### 2차 · 현재 게임에 시점과 좌표 기반 연결

기존 작업 상태와 별개인 렌더러·카메라 계층을 만들고, 2D와 개발용 2.5D가 같은 작업 데이터를 보도록 연결합니다. `project/pick/projectTerm`, 화면 이동·확대·핀치·창 크기 변경, 위치로 이동하기와 화면 위 안내창의 좌표를 공통으로 처리합니다. 카메라 설정은 작업 저장과 분리합니다.

**완료 기준:** 2D 화면과 기존 조작이 그대로 동작하고, 개발용 2.5D에서 시점만 바꿔도 작업 내용·검사 결과·점수·기록은 변하지 않아야 합니다. 일반 마우스 이동은 각도를 바꾸지 않아야 합니다. 아직 연결하지 않은 도구는 미리보기에서 사용할 수 있는 것처럼 표시하지 않습니다.

### 3차 · 제어판 기구 외형과 조립

소켓·릴레이·타이머·PLC부터 단자대·MCB·퓨즈 홀더·SMPS·서보 등 제어판 기구의 높이와 외장을 추가합니다. 철판·덕트·찬넬·스토퍼는 1차에서 정한 표현을 재사용합니다. 단순한 입체 형상에 기존 SVG의 정면 그림과 제품 표기를 활용합니다.

기구 이동·장착·제거, 타공·볼트 고정, 덕트 이음부와 커버 열기/닫기를 연결합니다. 기존 배치 제한과 판정은 같은 명령을 사용합니다.

**완료 기준:** 실제 게임 배치의 기구가 찬넬·철판 위에 알맞은 높이로 놓이고, 각도를 바꿔도 기구와 나사·커버의 선택 위치가 맞아야 합니다. 겹치는 몸체와 커버가 서로 뚫고 보이지 않아야 합니다.

### 4차 · 기구 조작과 정확한 단자 선택

단자별 표시 높이와 가려짐을 반영해 선택·강조 표시를 연결합니다. 견출지 편집과 단자 검색, 기구 해설, 릴레이·타이머 삽입과 제거, 퓨즈 교체, MCB·버튼·선택 스위치와 타이머 설정 조작을 연결합니다. 램프·기구 상태는 기존 시뮬레이터의 값을 표시합니다.

**완료 기준:** 가까이 붙은 단자를 정면·좌측·우측에서 정확히 고를 수 있고, 가려진 단자가 몸체를 뚫고 선택되지 않아야 합니다. 이름표·설명창·상태 표시는 읽기 쉬워야 합니다. 일반 버튼과 타이머 설정 조작은 기존과 같아야 합니다.

### 5차 · 전선 꽂기와 기본 배선

기존 배선 경로에 표시 높이를 연결합니다. 전선이 단자 높이에서 내려와 덕트 안으로 들어가고, 커버와 기구 몸체에 맞게 가려지도록 표현합니다. 전선 선택·꽂기·빼기·절단, 결선 안내와 단자 추적을 연결합니다. 배선 조작 중에는 시야 각도를 고정합니다.

**완료 기준:** 카메라를 움직여도 선 끝이 단자에서 떠 보이지 않고, 연결 단자·선 길이·회로 판정이 바뀌지 않아야 합니다. 같은 저장 작업을 2D와 2.5D에서 열었을 때 연결·검사 결과가 같아야 합니다. 커버에 가린 전선을 잘못 고르는 문제도 확인합니다.

### 6차 · 타이·헬리컬 밴드·테스터

케이블 타이와 전선 모양 조정, 헬리컬 밴드의 고정 구간과 끝부분, 테스터의 전압·도통 측정을 연결합니다. 정밀 작업 중 각도 고정과 안내선·측정값 위치를 검증합니다. 기존 경로 재사용과 고정 구간 계산을 활용하며 카메라 변화로 전선을 다시 변형하지 않습니다.

**완료 기준:** 타이를 움직여도 헬리컬 밴드로 감싼 구간은 고정되고, 밴드 끝부터 노출된 선이 움직여야 합니다. 화면 각도가 달라도 같은 두 단자에서 측정값이 같아야 합니다. 전선 정리가 선 길이·연결·채점에 미치는 기존 규칙을 유지합니다.

### 7차 · 조작판·컨베이어와 전체 모드 연결

조작판의 앞뒤 전환과 HMI·표시등·버튼 배선, 바닥에 놓인 갈색 R·파란색 T·초록색 E 전원선, 컨베이어·센서·구동부를 연결합니다. 장면 이동·전체 보기와 연습 안내, 시연, 채점표의 위치 표시, 고장 실습과 시험·자유 모드를 점검합니다.

**완료 기준:** 제어판에서 조작판·컨베이어로 이동해도 시점과 선택 위치가 자연스럽고, 기존 기준 작업이 똑같이 작동해야 합니다. 같은 저장 파일의 기구·배선·검사·채점과 모드별 기록을 유지해야 합니다. 보이는 단자와 안내 위치가 항상 일치해야 합니다.

### 8차 · 성능·호환성 마무리와 정식 배포

완성 배선과 전선 정리가 많은 장면으로 화면 이동·확대·조작을 측정합니다. 실제 학교 PC/통합 그래픽 환경에서 안정적인 60FPS를 목표로 하되, 측정 환경·해상도와 입력 지연을 기록한 뒤 판단합니다. 학교 PC를 직접 사용할 수 없으면 우선 측정 가능한 환경의 결과를 기록하고 실제 사용 결과로 보완합니다. 성능 점검은 각 차수에서도 수행하고, 이 차수에서 전체 장면을 마무리합니다.

정지한 화면은 불필요하게 다시 그리지 않고, 카메라 이동은 프레임당 한 번 처리합니다. 부품 재질은 묶음 이미지로 재사용하고, 전선 좌표는 배선이 바뀔 때만 갱신합니다. 반짝임·고해상도 그림자·전체 화면 후처리는 기본 범위에서 제외합니다. 도구를 옮길 때 기구 전체 그림을 매번 새 이미지로 만들지 않습니다.

WebGL을 사용할 수 없거나 장치에서 문제가 생기면 기존 2D로 돌아갑니다. `2D / 2.5D`, `정면 보기`, `각도 고정`의 동작과 설정 복원을 마무리합니다. Electron의 오프라인 실행·제한된 외부 접속·스크립트 정책을 유지하고, 라이브러리와 재질을 앱에 묶어 배포합니다.

**최종 완료 기준:** 기존 회귀 검사, 각도별 단자 클릭, 확대/핀치/창 크기 변경, 작업 저장·복원, GPU 사용 불가 시 2D 복구, Windows 설치형 실행과 자동 업데이트 검사를 통과해야 합니다. 확인한 성능 범위와 함께 정식 2.5D 선택 기능을 배포합니다.

# 2.19.0 · Supabase 온라인 랭킹

기존 기기 내 랭킹은 그대로 유지합니다. **메인 → 랭킹 → 온라인 랭킹 → 동의하고 온라인 사용**을 선택하면 이후 완료한 기록을 온라인에 등록합니다. 닉네임·점수·불량 개수·시간·등록일이 공개됩니다. 예전 기록은 자동 공개하지 않으며 **이 기기의 최고 기록 등록**으로 직접 등록할 수 있습니다.

## 프로젝트 설정: 한 번만 진행

1. Supabase 프로젝트의 왼쪽 **SQL Editor**를 엽니다.
2. **New query / +**로 새 입력창을 만듭니다.
3. [ranking.sql](../supabase/ranking.sql) 내용을 전부 복사해 붙여 넣고 **Run**을 누릅니다. `Success`가 나오면 완료입니다. 이 파일은 프로젝트의 랭킹 보관함과 등록·조회 규칙을 만듭니다. 다시 실행해도 기존 기록을 지우지 않습니다.
4. **Authentication → Sign In / Providers**에서 **Anonymous Sign-Ins**를 활성화하고 저장합니다. 대시보드 버전에 따라 Providers 안에 표시될 수 있습니다. 이메일 없이 브라우저·설치형 앱을 구분하기 위한 로그인입니다.
5. 업데이트한 앱의 온라인 랭킹을 켜고 **새로고침**을 누릅니다. 처음에는 빈 순위표가 정상입니다. 하나의 기록을 완료하거나 직접 등록한 뒤, 다른 기기의 온라인 랭킹에서 같은 기록이 보이는지 확인합니다.

앱에는 프로젝트 URL과 **공개용 Publishable key만** 포함합니다. 데이터베이스 비밀번호·Secret key·service_role key는 필요하지 않으며 배포하지 않습니다. 공개 키로 SQL 설정을 실행할 수 없으므로 1~4는 프로젝트 소유자가 대시보드에서 진행해야 합니다.

## 기록과 인증

- 온라인에는 익명 사용자별·종목별 최고 기록 하나씩, 최대 3행을 보관합니다. 기기 내 랭킹은 기존 닉네임별 방식입니다.
- 동일한 닉네임도 서로 다른 사람일 수 있어 짧은 식별 번호를 함께 표시합니다. 온라인 순위는 서버가 계산하며 동률은 공동 순위입니다. 조회는 상위 100개로 제한합니다.
- 시험은 점수 우선 → 시간, 선 따기는 직접 점검한 불량 개수 우선 → 시간, 고장은 무힌트 10연속 완료 시간 순입니다.
- 게임 결과는 클라이언트가 보고합니다. 서버는 값의 형식·범위·등록 간격을 검사하지만, 실제 작업 수행이나 조작된 앱의 점수를 완전히 증명하지는 않습니다. 특히 선 따기는 자기 점검 기록입니다.
- 인증 정보는 해당 브라우저 또는 설치형 앱의 저장 공간에 보관합니다. 로그인 토큰은 만료 시 갱신합니다. 저장 데이터를 삭제하거나 다른 기기를 사용하면 새 익명 사용자로 구분될 수 있으며 기존 익명 기록을 복구할 계정 로그인은 제공하지 않습니다.

## 오프라인과 저장 실패

기기 내 기록을 먼저 저장하고, 온라인 사용이 켜져 있을 때만 전송 대기열에 넣습니다. 대기열은 재시작해도 유지하며 최대 100개입니다. 잠깐의 통신 실패는 30초 후 재시도하고, 온라인 화면의 새로고침으로도 재시도합니다. 요청은 8초 후 중단합니다. 전송 중 새 기록이 생겨도 기존 대기열을 덮어쓰지 않으며 같은 완료 기록의 재전송은 중복 기록을 만들지 않습니다.

온라인 사용을 끄면 이후 자동 등록과 재시도를 중단하고 대기 기록은 보관합니다. 이미 공개된 최고 기록을 삭제하는 기능은 이번 버전에 포함하지 않습니다. 프로젝트 소유자는 Supabase에서 사용자 데이터를 관리할 수 있습니다.

`SQL 실행` 안내가 나오면 RPC 설정이 아직 없는 것입니다. `Anonymous Sign-Ins` 안내는 익명 로그인 설정을 확인합니다. 연결 실패는 네트워크·무료 프로젝트 일시 중지·서비스 상태를 확인하고 새로고침합니다. 유료 플랜으로 자동 전환하는 코드나 결제 기능은 없습니다. 서비스 무료 한도는 Supabase 정책을 따릅니다.

## 권한과 검증

원본 표는 외부에 노출하지 않는 `task1_private` 스키마에 만들고, 일반 사용자 접근 권한을 제거하며 RLS를 켭니다. 조회는 제한된 공개 RPC만 사용하고, 등록 RPC는 인증된 사용자만 호출합니다. 소유자 ID를 요청값으로 받지 않고 인증 정보에서 결정합니다. 다른 사람의 행을 수정·삭제하는 API는 제공하지 않습니다.

Windows 앱은 해당 프로젝트의 4개 인증·랭킹 경로만 HTTPS로 허용합니다. 다른 외부 탐색·팝업 차단을 유지하고, CSP에도 이 프로젝트 주소만 추가합니다. 비밀 키는 사용하지 않습니다.

자동 검사에는 통신 모의 응답을 사용한 동의·오프라인 재전송·토큰 갱신·브라우저 표시와 PostgreSQL(PGlite)에서의 SQL 권한·값 검증·최고 기록·동률·등록 간격 검사가 포함됩니다. SQL 검사에서는 Supabase의 `auth.uid()` 환경을 모사합니다. 이 검사가 실제 Supabase 프로젝트의 설정 완료나 인터넷 연결을 대신하지는 않습니다.

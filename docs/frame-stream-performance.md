# v2.45.0–2.45.1 · 한 칸 보기와 내부 프레임 전달

책상·바닥·옆면·윗면 버튼은 선택한 칸만 표시합니다. 바깥 장면은 잘라내며, 화면 비율이 다른 경우 생기는 여백에는 옆 칸을 표시하지 않습니다. 휠·확대 버튼·가운데 버튼 드래그·빈 배경 드래그·두 손가락 확대는 해당 칸 안으로 제한합니다. **모든 칸 보기** 또는 `0`은 네 칸의 전체 배치로 전환합니다. 제어판·조작판·컨베이어 버튼은 그 물체가 있는 칸에서 확대합니다.

v2.45.1에서는 검색한 단자를 기준으로 해당 칸을 선택하고, 연결 전체는 **모든 칸 보기**에서 확인하도록 보완했습니다. 선택·카메라 취소 시 임시 도형과 프레임 전달을 함께 해제합니다. 아래 성능 측정은 v2.45.0의 동일한 카메라 렌더러를 사용한 결과입니다.

## 프레임 전달 방식

앱 안에서 실행하는 `Worker`와 `OffscreenCanvas`를 사용합니다. 입력이 멈춘 뒤 원본 SVG의 정적 장면을 여유 영역을 포함한 이미지로 준비하고, 확대·이동 중 최신 카메라 좌표를 작업자에게 전달합니다. 작업자는 이미지를 잘라 확대·이동한 프레임을 캔버스에 그립니다. 이때 정적 SVG 레이어의 레이아웃·페인트를 쉬게 하며, 실시간 동작 표시는 별도 SVG 레이어를 사용합니다.

조작이 끝나면 현재 카메라에서 원본 SVG를 다시 표시합니다. 부품·배선·그래픽 설정·판 위치가 바뀌면 캐시를 폐기합니다. 늦게 도착한 이전 프레임은 표시하지 않으며, 선택한 칸이나 테마가 다른 이미지도 재사용하지 않습니다. 작업·배선·채점·저장 상태는 원본 모델이 관리합니다.

이미지가 준비되지 않았거나 확대 범위를 벗어나거나 돋보기를 사용하는 경우에는 SVG로 표시합니다. Worker/OffscreenCanvas를 지원하지 않거나 생성에 실패해도 SVG 조작을 계속 사용할 수 있습니다. 준비 중인 이미지 한 장과 작업자 이미지 한 장으로 대기열을 제한하고, 새 이미지가 도착하면 이전 비트맵을 닫습니다. 이미지 준비는 포인터 조작이 멈춘 뒤로 미룹니다.

## 추가 최적화

- 휠 입력을 다음 화면 프레임에 한 번만 반영하고, 연속 휠 조작에서는 작업 영역 크기를 재사용합니다.
- 화면 좌표 행렬 대신 SVG 조상들의 모델 변환을 합성해 경로마다 발생하던 동기 레이아웃 조회를 없앱니다.
- 기구의 그리기 순서만 바뀌면 표면 바인딩을 재계산하지 않습니다. 같은 경로의 투영 계획도 재사용합니다.
- 전선 꼭짓점은 주변 타일에 있는 표면만 검사합니다. 전체 표면을 검사한 기준 결과 및 브라우저의 실제 변환 행렬과 일치하는지 회귀 검사합니다.

## 변경 전후 측정

동일한 1440×900 헤드리스 Chromium에서 배선 122개, 전체 그래픽 효과를 켠 기준 작업을 사용했습니다. 매 프레임 휠 이벤트 4개를 보내 확대·축소를 번갈아 90프레임씩, 버전마다 3회 측정했습니다. 모드 진입과 이미지 준비를 끝낸 뒤 측정하며 실시간 회로 타이머는 멈춥니다. 프레임 시간은 실제 `requestAnimationFrame` 사이 간격입니다. 사용자 PC의 실측 FPS나 영상 인코더의 FPS가 아닙니다.

| 항목 | v2.44.1 | v2.45.0 |
|---|---:|---:|
| 프레임 간격 중앙값 · 3회 통계의 중앙값 | 249.9ms | 16.7ms |
| 프레임 간격 p95 · 3회 통계의 중앙값 | 333.5ms | 33.3ms |
| 50ms 초과 프레임 · 270회 합계 | 270 | 3 |
| 입력 4개 처리 시간 중앙값 · 3회 통계의 중앙값 | 90.2ms | 0.1ms |
| 카메라 반영 · 준비 12 + 측정 360개 입력/회 | 372회 | 102회 |
| 작업자에서 실제 도착한 화면 프레임/회 | 0 | 99~101 |

50ms를 넘긴 프레임은 이 조건에서 약 **98.9% 감소**했습니다. 변경 후에도 3회의 p95는 16.8~33.4ms로 차이가 있었고, 긴 프레임 3개가 남았습니다. 이 결과는 캐시가 준비된 확대·이동 구간의 측정입니다. 최초 이미지 준비, 큰 확대 후 원본 복귀, 부품·배선 편집까지 모두 60FPS를 보장한다는 뜻은 아닙니다.

배선 편집은 별도 비교로 40개·122개 전선에서 각 40회 제거·복원을 측정했습니다. 모드 진입의 예약 카메라 작업을 두 프레임 기다린 뒤 양쪽 모두 같은 카메라를 설치해, 서로 다른 배율이 측정되지 않게 했습니다. 122개 전선의 편집 프레임 중앙값은 **516.6 → 366.6ms**, p95는 **716.7 → 516.7ms**였습니다. 편집 시 50ms 초과 프레임은 양쪽 모두 40/40개로 남아 있습니다. 확대·이동보다 편집 쪽에 추가 최적화 여지가 크며, 편집 결과는 한 차례의 보조 측정입니다.

| 배선 편집 보조 측정 | v2.44.1 | v2.45.0 |
|---|---:|---:|
| 40개 · 편집 프레임 중앙값 / p95 | 150.1 / 300.1ms | 133.3 / 216.7ms |
| 122개 · 편집 프레임 중앙값 / p95 | 516.6 / 716.7ms | 366.6 / 516.7ms |
| 122개 · 동기 편집 처리 중앙값 | 477.2ms | 313.6ms |
| 122개 · 포인터 이동 p95 | 50.1ms | 50.0ms |

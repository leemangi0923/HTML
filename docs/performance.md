# 2.5.2 성능 점검

단일 HTML인지 JS/CSS가 분리되어 있는지는 유지보수와 파일 캐시에 영향을 주지만, 마우스를 움직일 때의 반복 계산을 없애지는 않습니다. 이번에는 확인된 런타임 병목을 최적화했습니다.

## 확인한 병목과 변경

- 전선 강조를 찾는 `hoverHL` / `wireGrab`이 포인터 이동마다 전체 전선의 경로를 다시 구하고 모든 선분을 검사했습니다.
- 전선 경로를 재사용하고, 각 경로의 경계·선분 길이를 준비해 가까운 후보만 정밀 검사합니다. 거리 비교에는 제곱 거리를 사용하고 최종 후보만 좌표·각도로 변환합니다.
- 모양이 바뀌지 않은 SVG에도 `innerHTML`을 다시 지정해 노드를 교체했습니다. 이제 내용이 같으면 기존 노드를 유지합니다.
- 고빈도 포인터 이벤트의 강조 갱신을 `requestAnimationFrame`으로 합칩니다. 입력 상태는 즉시 갱신하며, 놓기·취소 시 마지막 좌표와 표시를 동기화합니다.
- 캐시는 저장 데이터가 아닌 일시적인 계산 자료입니다. 단자 재생성·작업 변경·되돌리기·타이 이동·밴드 이동·작업판 다시 그리기에서 무효화합니다. 구버전 저장 데이터 변환은 임시 경로를 직접 계산합니다.

경로 배열은 캐시에서 읽는 값이므로 호출자는 직접 수정하지 않습니다. 전선/타이/기구 상태를 바꾸는 새 코드는 기존 `commit` / `buildTerms` / `renderWorld` 경로를 사용하거나 `invalidateWireGeometry()`를 호출해야 합니다.

## 같은 환경에서의 측정

Chromium, 1440×900, 외부 글꼴 차단, 예시 전체 배선·타이 12개 장면을 사용했습니다. 손/전선 도구별로 포인터 위치를 바꾸며 강조 처리를 50회 측정했습니다. 아래 수치는 같은 클라우드 환경에서의 한 실행 결과이며 전체 화면 FPS나 다른 기기의 성능 보장이 아닙니다.

| 측정 | 변경 전 (`a60ca44`) | 변경 후 |
|---|---:|---:|
| 손 도구 강조 처리 중앙값 | 19.3ms | 0.8ms |
| 손 도구 강조 처리 95백분위 | 23.1ms | 2.7ms |
| 전선 도구 강조 처리 중앙값 | 13.6ms | 1.4ms |
| 같은 강조 내용 20회 처리 시 SVG 노드 교체 | 20회 | 0회 |

재현:

```sh
npm ci
npx playwright install chromium
npm run benchmark
```

기존 Chromium을 쓰려면 `CHROMIUM_PATH=/usr/bin/chromium npm run benchmark`를 사용합니다. 이전 파일과 비교하려면 다음처럼 동일한 스크립트에 HTML 경로를 전달합니다.

```sh
git show a60ca44:index.html > /tmp/simulator-before.html
npm run benchmark -- /tmp/simulator-before.html
npm run benchmark
```

벤치마크는 별도 브라우저 저장 공간을 사용하고 저장소 파일을 수정하지 않습니다. 계산 경로 재사용, 화면 갱신 합치기, 빠른 드래그의 마지막 입력, 전선/타이 변경, 거리 계산의 정확성은 자동 회귀 검증에 포함합니다. 시간 수치는 머신 부하에 영향을 받으므로 CI에서 고정 ms 기준으로 통과시키지 않습니다.


## 2.7.2 휠 버튼 드래그

휠을 누른 채 움직일 때 입력 이벤트마다 `viewBox`를 쓰고 다음 이벤트에서 화면 크기를 읽던 경로를 수정했습니다. 카메라 좌표는 즉시 계산하되 DOM 반영은 rAF에 묶고, 제스처 시작 시 읽은 화면 크기를 재사용합니다. `applyCam`은 크기를 먼저 읽은 뒤 변경된 `viewBox`만 씁니다. 돋보기·커서 추종도 이동 중 프레임당 한 번으로 제한하며 포인터 강조는 종료 시 갱신합니다. 놓기·취소·캡처 해제·창 포커스 이탈에서 마지막 입력을 잃지 않도록 동기화합니다.

Chromium 1440×900, 예시 배선의 SVG 기구·배선 노드 5,164개에서 같은 작업 안에 이동 이벤트 120개를 보낸 결과입니다.

| 입력 120개 한 묶음 | 변경 전 (`3bf7dd5`) | 변경 후 |
|---|---:|---:|
| SVG `viewBox` 쓰기 | 120회 | 1회 |
| 작업판 크기 읽기 | 120회 | 0회 |
| 카메라 적용 호출 | 120회 | 1회 |
| 이벤트 전달 동기 처리 시간 | 785.9ms | 1.7ms |

이 시간은 이벤트 전달 구간만 측정하며, 이후 rAF의 적용·렌더링 시간은 포함하지 않습니다. 합성 이벤트를 한꺼번에 전달한 결과이므로 실제 마우스의 프레임 속도나 동일 비율의 체감 향상을 의미하지 않습니다. 실제 FPS는 장면·디스플레이·브라우저·기기에 따라 달라집니다.

```sh
CHROMIUM_PATH=/usr/bin/chromium npm run benchmark:pan
# 이전 HTML 파일과 비교
CHROMIUM_PATH=/usr/bin/chromium node scripts/benchmark-pan.cjs /tmp/before.html
```


## 2.15.0 완성 배선의 부분 갱신과 타이 이동

기준 버전 `d00152f`(2.14.0)과 비교했습니다. 먼저 기존 포인터·휠 버튼 이동 벤치마크로 이미 입력을 프레임 단위로 묶고 있음을 확인했습니다. 추가로 확인한 병목은 다음과 같습니다.

- `renderWorld`가 버튼 상태 변화에도 전선 경로 캐시를 전부 지우고 5천여 SVG 노드를 포함하는 작업판을 교체했습니다.
- 조작판 앞면의 단자 좌우 반전 계산에서 매번 단자를 재생성했습니다.
- 타이를 끌 때 그림만 rAF에 묶고, 실제 위치·배선 계산은 모든 포인터 이벤트에서 수행했습니다.

변경 내용:

- 순서가 있는 기구·전선·커버·조작판 부분을 유지하고 바뀐 부분의 자식 노드만 교체합니다. 전선은 기존의 핀→나사→몸체→슬리브 및 최근 전선 강조 순서를 유지합니다.
- 표시 상태만 바뀌는 `renderWorld(false)` 경로에서는 물리 전선 경로를 재사용합니다. 일반 `renderWorld()`·`commit`·`buildTerms`는 기존처럼 경로를 무효화하므로 기구·배선 수정과 되돌리기를 반영합니다.
- 앞면 단자 투영은 단자 버전에 맞춰 보관하고, 앞면 경로는 뒷면 경로와 별도로 보관합니다. 압착단자·선 그림은 경로와 단자 객체·최근 강조가 같으면 재사용합니다.
- 타이 이동은 프레임마다 마지막 포인터 위치로 한 번 계산합니다. 타이가 연결된 전선의 변형만 무효화하고, 기본 전선 경로는 유지합니다. 놓기·취소·캡처 해제·포커스 이탈에서는 대기 중인 위치를 먼저 반영하고 예약 프레임을 취소합니다.

Chromium, 1440×900, 외부 글꼴 차단, 완성 예제와 타이 12개를 사용한 같은 환경의 한 실행 결과입니다.

| 측정 | 2.14.0 | 2.15.0 |
|---|---:|---:|
| PB1 누름·뗌 20회: 기본 경로 계산 | 4,400회 | 0회 |
| 같은 조작에서 추가/제거한 SVG 노드 (각각) | 193,720개 | 14,410개 |
| PB1 누름·뗌 한 쌍의 동기 처리 중앙값 | 68.8ms | 11.3ms |
| 같은 동기 처리 95백분위 | 165.7ms | 37.0ms |
| 타이 이동 이벤트 120개: 실제 위치 계산 | 120회 | 1회 |
| 같은 이동에서 기본 경로 재계산 | 362회 | 0회 |
| 같은 이동에서 추가/제거한 SVG 노드 (각각) | 5,186개 | 76개 |
| 입력 120개 전달 구간 동기 처리 | 13.9ms | 2.1ms |

부분 갱신용 그룹이 추가되어 전체 SVG 노드는 5,186→5,708개이고, 반복해서 제거·생성하는 노드 수가 감소합니다. 위의 시간은 한 실행에서 측정한 JavaScript 동기 처리 시간입니다. 프레임의 페인트 시간·실제 화면 FPS는 포함하지 않으며, 다른 기기의 성능이나 같은 비율의 체감 향상을 보장하는 수치는 아닙니다. 노드 수와 계산 횟수는 시간 측정과 함께 비교합니다.

재현:

```sh
git show d00152f:index.html > /tmp/html-v214-before.html
CHROMIUM_PATH=/usr/bin/chromium npm run benchmark:scene -- /tmp/html-v214-before.html
CHROMIUM_PATH=/usr/bin/chromium npm run benchmark:scene
CHROMIUM_PATH=/usr/bin/chromium npm run benchmark
CHROMIUM_PATH=/usr/bin/chromium npm run benchmark:pan
```

장면 벤치마크는 합성 포인터 입력을 사용해 입력 처리·DOM 교체·계산 횟수를 측정합니다. 사용자 브라우저의 저장 공간과 분리됩니다. 시간 임계값을 자동 검사의 통과 조건으로 사용하지 않습니다.

검증은 실제 동작 상태에 맞는 기구 표시, 바뀌지 않은 SVG 노드와 전선 경로 유지, 타이의 마지막 좌표 저장·되돌리기, 취소·캡처 해제·포커스 이탈 후 늦은 프레임 방지를 포함합니다. 기존 회로·채점·밴드·타이·앞뒤 반전·검색·실전 고장 실습 검사도 함께 실행합니다. 같은 조건으로 렌더링한 변경 전·후 앞면·뒷면·PLC ON·컨베이어 운전 작업판 네 장면은 픽셀이 일치했습니다.

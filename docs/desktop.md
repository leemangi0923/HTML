# 설치형 1과제 제작 시뮬레이터 · v2.17.0

## 사용자: 설치하고 실행하기

Windows 10/11 64비트(x64)를 대상으로 합니다. Node.js·Godot·별도 브라우저 설치가 필요 없습니다.

1. [버전별 다운로드](https://github.com/leemangi0923/HTML/releases)에서 `task1-simulator-setup-v2.17.0-x64.exe`를 받습니다.
2. 설치 파일을 실행하고 설치 위치를 선택합니다. 현재 Windows 사용자에게 설치하며 관리자 권한을 요청하지 않습니다.
3. 바탕화면 또는 시작 메뉴의 **1과제 제작 시뮬레이터**를 실행합니다.
4. **F11**로 전체 화면을 켜고 끕니다. 게임 안에서 확대·이동하는 조작은 웹 버전과 같습니다.

게임과 그림을 앱 안에 포함해 인터넷 없이 실행합니다. 외부 웹 글꼴 대신 Windows의 맑은 고딕 등 시스템 글꼴을 사용합니다. 게임 메뉴의 **배선 목록 → TXT 저장 / CSV 저장**은 운영체제의 파일 저장 창을 엽니다.

이번 배포에는 게시자 코드 서명이 없습니다. 인터넷에서 받은 설치 파일을 실행할 때 Windows가 게시자 확인 안내를 표시할 수 있습니다.

## 저장과 업데이트

자유·시험·연습 통과 기록·고장 실습·설정은 이 앱에 자동 저장합니다. Windows의 `%APPDATA%\Task1Simulator`를 사용하며 메뉴 **도움말 → 저장 위치 열기**로 확인할 수 있습니다. 앱 버전이 바뀌어도 같은 폴더와 같은 내부 주소를 사용합니다. 종료 직전에 현재 작업을 저장합니다.

**브라우저의 저장 공간과 설치형 앱의 저장 공간은 별개입니다.** 앱을 설치해도 기존 웹 작업을 지우거나 자동으로 가져오지 않습니다. 설치형 앱에서는 새 작업으로 시작합니다. 기존 배선 목록 텍스트 불러오기는 자유 모드에서 계속 사용할 수 있습니다.

v2.17.0부터 **자동 업데이트**를 지원합니다. 앱을 켜고 약 15초 뒤, 이후 4시간마다 새 정식 버전을 확인합니다. 메뉴 **도움말 → 업데이트 확인**으로 바로 확인할 수도 있습니다. 새 버전 알림에서 **업데이트 받기**를 누르면 다운로드하고, **저장하고 재시작**을 눌렀을 때만 설치·재실행합니다. 창을 닫거나 게임을 끝내는 것만으로 설치하지 않습니다.

진행 중인 연습 레슨은 완료한 뒤 적용할 수 있고, 자유·시험·고장 실습 작업이 저장되지 않으면 재시작을 막습니다. 인터넷이 끊겨도 게임은 계속할 수 있으며 나중에 다시 확인할 수 있습니다. 다운로드 중에도 게임을 계속할 수 있습니다.

**v2.16.1에는 업데이트 코드가 없으므로 v2.17.0을 한 번 직접 설치해야 합니다.** 이후 버전부터 앱 안에서 업데이트를 받을 수 있습니다. HTML 수정·푸시 후 Windows 빌드는 자동 생성되고, 실제 앱 업데이트 배포에는 새 버전 태그와 Releases 게시가 필요합니다. 기본 제거 설정에서도 앱 저장 데이터는 남겨 재설치 후 다시 사용할 수 있게 합니다.

## 개발자: 실행·빌드

개발에는 Node.js **22.12 이상**이 필요하며, 자동 빌드는 Node.js 24를 사용합니다. Electron 45.2.3, electron-builder 26.18.0을 정확한 버전으로 고정했습니다.

```sh
npm ci
npm start
# 실제 Electron 실행·파일 저장·재시작 검증
npm run test:desktop
# 실행 폴더로 패키징
npm run dist:dir
# Windows에서 NSIS 설치 파일 빌드
npm run dist:win
```

결과는 `dist/task1-simulator-setup-v2.17.0-x64.exe`입니다. `dist`와 자동 생성 HTML은 Git에 넣지 않습니다. 패키지에는 게임 HTML·Electron 실행 코드·앱 아이콘만 포함합니다. 보관 중인 Godot 프로젝트·모델·이전 ZIP·개발 테스트는 설치 파일에 포함하지 않습니다.

`desktop/prepare.cjs`가 `index.html`에서 데스크톱 전용 오프라인 HTML을 만듭니다. 외부 글꼴 링크를 제거하고 실제 인라인 게임 스크립트의 SHA-256 해시를 사용한 CSP를 추가합니다. 원본 웹 HTML은 그대로 사용할 수 있습니다.

렌더러는 `sandbox: true`, `contextIsolation: true`, `nodeIntegration: false`이며, 파일 저장은 현재 앱의 메인 프레임에서 텍스트/CSV 저장 요청만 받습니다. 앱은 외부 탐색과 새 창을 차단합니다. `task1://app/index.html` 주소가 설치 경로·버전과 무관한 저장 기준입니다.

테스트에서만 `TASK1_USER_DATA_DIR`로 임시 저장 폴더를 지정합니다. `TASK1_EXECUTABLE`을 설정하면 패키징한 실행 파일로 같은 검사를 수행합니다. Linux 컨테이너의 자동 테스트는 가상 X 화면과 `--no-sandbox` 런처 인수를 사용합니다. 제품 코드의 렌더러 보안 설정은 유지합니다. Windows 설치·제거의 최종 확인은 Windows에서 수행해야 합니다.

## GitHub에서 설치 파일 만들기

`.github/workflows/desktop.yml`은 `main`의 게임/데스크톱 코드 변경 및 수동 실행 때 Windows에서 앱 검사를 실행한 뒤 NSIS 설치 파일을 만듭니다. Actions의 **Windows installer → task1-windows-installer** 아티팩트에서 설치 파일과 SHA-256을 받을 수 있습니다. 일반 빌드 아티팩트는 14일 동안 보관합니다.

태그 `v2.17.0`처럼 패키지와 같은 버전의 태그를 푸시하면 Windows 검사·빌드가 성공한 뒤 GitHub Releases에 설치 파일과 해시를 올립니다. 릴리스 자산은 일반 빌드 아티팩트의 14일 보관 기간과 별도로 유지됩니다. 버전 업데이트 시 `package.json`·`package-lock.json`·`APP_VER`을 함께 올립니다.


## 업데이트 배포와 검증

`electron-updater` 6.8.11을 사용하고, GitHub의 `leemangi0923/HTML` 정식 릴리스에서만 업데이트를 받습니다. electron-builder가 설치 파일의 버전·주소·SHA-512를 담은 `latest.yml`과 앱 안의 `app-update.yml`을 생성합니다. Windows 빌드 작업은 EXE·SHA-256·`latest.yml`을 함께 Releases에 게시합니다. 개발 실행과 Linux 앱에서는 실제 업데이트 확인을 하지 않습니다.

게임 렌더러의 외부 연결 차단을 유지하고 업데이트 네트워크는 메인 프로세스의 전용 세션에서 처리합니다. 렌더러는 정해진 확인·다운로드·적용 동작만 요청할 수 있습니다. 자동 다운로드·종료 시 자동 설치·이전 버전으로 되돌리기·시험판 배포 수신을 끕니다. 현재 릴리스는 코드 서명이 없으므로 Windows 게시자 서명 검증을 요구하지 않으며 HTTPS와 배포 메타데이터의 파일 해시로 다운로드 무결성을 확인합니다.

`npm run test:updater`는 오프라인·중복 클릭·다운로드 실패·완료 후 명시적 적용·저장소 flush 순서·일반 종료 시 자동 설치 금지를 검사합니다. Electron 실행 검사는 실제 알림 표시, 진행 중인 연습과 저장 실패 때 적용 차단, 저장 성공 뒤 적용 요청, 기록 복원을 확인합니다. 업데이트 상태는 테스트에서 모의 이벤트로 공급합니다. Windows CI에서는 개발 앱과 패키징 EXE에 같은 검사를 실행합니다.
